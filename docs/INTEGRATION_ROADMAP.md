# 🧩 扩展路线：先闭环，再增加能力

运行链路统一为“观测 → 候选动作 → 选择 → 执行 → 评估”。不同项目提供这条链路里的组件，不各自发展成一套并列工作台。当前界面与控制保持原样；新增批量评测在独立进程运行。

## 这几个仓库值得借鉴什么

以下是源码与公开记录核对，核对日期 2026-09-21。上游成绩属于上游，不能移植成行知的成绩。

| 项目与核对版本 | 有用的部分 | 适用边界 |
| --- | --- | --- |
| [CIGI](https://github.com/friendlyCamel/CIGI-Can-I-Get-It-/tree/0c7c78e6674aaee15e87cdd654bc3cae29618d5b) | 找不到目标时主动换视角；短期意图记忆；丢失后重捕获 | 两连杆模拟器与合成 bbox；132 个底层候选由代码评分，Jev 选语义。抓取就绪只检查估计距离与图像居中，没有完整物理抓放 |
| [Jev-as-Policy](https://github.com/YuanKJing/Jev-as-Policy/tree/248f5b5701a659c3cd5f666a8b086f714e60c397) | 连续伺服、接触时降速、目标滤波、推理中更新状态 | 与现有两阶段 XYZ 接近；输入是仿真状态。连续运行要配套过期指令失效、端点约束和停止语义，不能只复制速度参数 |
| [openarm-jev-lab](https://github.com/tripathiarpan20/openarm-jev-lab/tree/c89a73f6ff10094acc3d27e45ef91a31791eadb2/experiments/jev-controller) | 独立 LIBERO-PRO worker；几何候选；标准化短动作块；保留官方成功判定 | 使用仿真物体坐标、碰撞边界与接触，非图像理解。改良菜单旋转为零；公开成功是个别开发局，不能当套件成功率 |
| [RoboJEV](https://github.com/lykycy123/RoboJEV/tree/aa82be09603032b0e196f2e4aaa7277d54eb7b42) | 开发／测试种子分离；同条件规则对照；保留失败；Wilson 区间；测量夹爪力 | 三类自建任务、结构化仿真状态。公开 Jev 结果为 10/10、10/10、8/10，仍是小样本和任务专门设计；不是原始图像或通用操作成绩 |

另有同名的 [alee792/robojev](https://github.com/alee792/robojev)，面向 WidowX 真机，值得参考异步响应过期处理和离线重询问。当前没有将其真机驱动接入 Panda 仿真。

CIGI、Jev-as-Policy 使用 MIT；RoboJEV 使用 Apache-2.0。当前仅参考架构，未复制这些仓库的源码、模型或录像。以后移植代码需保留相应许可证与署名。

## 当前落地与后续顺序

**已经落地：统一评测。** 固定任务／种子、独立环境、官方成功判断、步骤／调用预算和逐局证据，详见 [Benchmark](BENCHMARKS.md)。Meta-World 已跑官方脚本策略；LIBERO 目前只完成可选状态接口，仍需在其独立环境验证。没有新增另一套浏览器控制模式。

**下一步：定位执行问题。** RoboJEV 提高了 Panda 示例夹爪的伺服增益并测量接触力；行知仍使用资产原有增益。这个差异值得检查，但不能据此认定它就是掉块原因。先记录下降时的双侧接触、法向力、物体滑移和指令，再分别比较接触降速、抓取稳定条件或夹爪参数。物理条件变化必须同时应用到规则与模型对照，不能只改善模型组。当前物理参数未改。

**然后：主动感知。** 在目标丢失或深度不可靠时，允许模型选择重新观察，保存最后可靠观测及其时间。把 CIGI 的记忆思路接到现有感知层，沿用同一控制器。意图持续需要安全和进展条件，不照搬固定保持 12 步；任何程序覆盖模型动作都单独记录。

## Jev、VLA、世界模型怎样协作

**VLA 与 WAM 在这里承担不同职责。** VLA 是动作策略：图像＋任务＋机器人本体状态 → 短动作块。WAM 这个名称在不同项目里可能指动作生成，也可能指动作条件预测；行知暂时只预留后者的接口设计，不安装模型、不增加运行模式。当前可运行的仍是既有 Jev／Chat／规则策略，尚无训练好的 VLA 或 WAM。

先尝试一条清晰的链路：VLA 从图像与任务生成短动作候选，Jev 基于允许的观测与候选说明做选择，执行器执行一个短块，再重新观察。需要 VLA 支持产生多个可比较候选；如果只有一个动作块，Jev 更适合做继续／重新观察／拒绝执行的判断，不能声称进行了轨迹优选。

| 组件 | 统一接口的职责 | 当前状态 |
| --- | --- | --- |
| 观测适配 | 声明状态、检测结果或图像来源，以及坐标系、时间和有效性 | 内置观测已有；外部 benchmark 目前仅状态 |
| 候选生成 | 输出有界动作或短动作块；可来自几何控制器或未来 VLA | 现有几何／短步候选；VLA 尚未接入 |
| Jev 选择 | 从有限选项选择并保留各自概率 | 已有原生接口；不将选择概率解释为成功概率 |
| WAM 预测接口（待开发） | 输入观测与候选动作块；返回预测状态／画面、预测时域与不确定性 | 仅保留设计；现有 MuJoCo 预演是物理模拟 |
| 执行与评估 | 转换动作并检查实际结果，不能由策略自报成功 | 内置与 Meta-World 链路已验证 |

VLA 动作接入前必须明确末端／关节空间、坐标系、单位、频率、夹爪正负号和动作块长度。世界模型的预测是估计，不能替代实际碰撞与任务验证。

比较按两组推进：当前先用 Meta-World 的相同状态、任务和预算比较 Jev 与 GPT；随后在原版 LIBERO 接入与该机器人和任务套件匹配的 VLA checkpoint，固定图像翻转／缩放、动作反归一化、初始化等待步数与官方初态。论文公开分数只有在版本和完整协议一致时才可直接对照，不能与当前自选 6 局并列排名。

视觉组先比较 **VLA 单独运行**与**同一 VLA＋Jev 选择**。Jev 接收候选说明和显式感知适配器产生的结构化证据，不能额外获得仿真物体真值。保存适配器版本与耗时；组合总耗时包括感知、VLA 和 Jev，不能只报最后一次请求。WAM 以后再作为第三组消融加入。三组都由 benchmark 判断成功，并报告失败、调用、延迟和执行步数。

这些是扩展接口设计，不是已集成的能力。当前不会为 VLA 或世界模型添加空的界面开关。

## RSI 放在离线改进循环

这里 RSI 指递归自我改进。第一阶段改善的是系统的提示、状态表达和候选生成，而不是修改托管 Jev 的模型权重。

1. 在开发清单运行并归类失败：看错、选错、执行偏差、接口异常或预算不足。
2. 只针对一种问题提出小改动，记录修改前后代码／提示指纹。
3. 用完全相同的案例与预算做旧版／新版配对实验，保留全部失败。
4. 通过回归后冻结版本，再用保留测试集评估；未改善或安全指标退化则不采用。

开发过程不能反复查看保留测试集后继续调参，再把它称为未见测试；后续多轮优化应轮换新的保留集。升级条件要提前规定，不仅比较总成功率，还检查单任务退化、接触异常和成本。自动发布、替换当前可用版本和持续付费实验都不是这个离线循环的默认动作。
